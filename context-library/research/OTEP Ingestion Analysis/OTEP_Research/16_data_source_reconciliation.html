OTEP — Data Source Reconciliation

Two sources feed GIG and STIP opportunities into OTG — WD STIP GIG Masterlist and officer self-posting. This page maps the schema differences, quantifies the gaps, and proposes a single canonical ingestion format.  ·  As at 10 June 2026

⚠
Critical finding: most STIPs are invisible to OTEP. WD manages 45 STIP opportunities in 2026. Only 7 appear in OTG GIGS_V2_REPORT — the source OTEP ingests from. 38 STIPs are being run entirely outside OTG (via WD + FormSG), meaning OTEP is currently missing the majority of the STIP catalogue. The same pattern affects GIG, where ~7 WD-managed GIGs are confirmed on OTG against 28 active in WD.

Key schema and data gaps

Application vs Program dates
2 pairs
WD maintains separate Application start/end and Program start/end. OTG likely stores only one date pair. Median gap: 28 days between app close and program start. OTEP needs to confirm which OTG date field maps to which WD date.
WD-only structured fields
5 fields
Target Audience (97%), Competencies (92%), Pre-requisites (94%), Agency POC (99%), Vacancies (92%) — all well-filled in WD, all missing as dedicated fields in OTG. In OTG, this content is embedded in the Description blob.
Job Family classification
13 families
WD organises opportunities by Job Family (SS, SD, ICT-SS, PE, P&P, PC, FP, HR, OD…). OTG has no equivalent — it uses the [Type] prefix only. OTEP currently has no job family dimension for filtering or matching.
Time commitment format
Free text
Both WD (83% filled) and OTG store time commitment as unstructured free text. Examples: "29 Jan 2026, 9am to 12pm", "1-1.5 days/week", "6 months". A structured field (hours/week or days/week) would be needed for reliable filtering in OTEP.
Vacancies vs sign-ups gap
Demand data
WD tracks Vacancies (92%), Sign ups (49%), Actual Matches (32%). OTG GIGS_V2_REPORT has applicant counts. These are the same concept from different angles — but the two sources aren't linked, making demand-supply analysis difficult.
WD type error
1 record
One WD record has Type="NLB" instead of "GIG" (NLB GIG, PE job family). Data entry error in the masterlist. If WD is used as a direct source, type validation would be needed upstream of OTEP ingestion.

Reconciliation recommendations

1
Add WD Masterlist as a direct ingestion source for GIG and STIP
Rather than relying on manual WD→OTG entry, OTEP should ingest GIG and STIP directly from the WD Masterlist. This unlocks all WD-managed opportunities (78 records, 53 active) regardless of whether they've been posted to OTG. OTG self-posted GIGs/STIPs would continue to be ingested from GIGS_V2_REPORT. De-duplication logic needed for records that appear in both sources.
Highest impact — unblocks ~46 invisible opportunities
2
Confirm OTG date field mapping: Program dates or Application dates?
OTG has one StartDate and one EndDate field. WD has four (Application Start/End + Program Start/End). The R9 "start date missing" validation is firing against OTG's StartDate — but it's unclear whether this maps to Application Start or Program Start. Since Program Start is 99% filled in WD and Application Start is 91%, confirming this mapping could change the DQ picture for GIG and STIP significantly. Recommendation: treat OTG StartDate = Program Start Date.
Directly affects R9/R10 validation logic
3
Standardise the upload template for OTG self-posted GIGs and STIPs
Officers self-posting on OTG currently enter into a free-form creation form. The WD Masterlist's structure (Job Family, Target Audience, Competencies, Prerequisites, POC) should be the standard for all GIG and STIP postings. A shared upload template — matching the canonical schema — would ensure self-posted records are as structured as WD-managed ones. Note: OTEP cannot modify the OTG creation form (existing constraint), but a pre-upload template is feasible.
Medium impact — improves data quality for ~29 self-posted GIGs
4
Clarify the application journey: OTG apply vs FormSG
WD-managed STIPs and GIGs use FormSG as the application channel. OTG serves as a discovery layer only — the "Apply" action redirects to FormSG. This means OTG applicant counts will be near-zero for WD-managed opportunities (confirmed in our engagement analysis: 84% zero-applicant rate). OTEP should use FormSG sign-up counts (from WD) rather than OTG applicant counts as the demand signal for these types.
Fixes misleading zero-applicant metric for WD-managed opps
5
Fix the WD type error (NLB record) and add upstream validation
One WD record has Type="NLB" instead of "GIG" — a data entry error. If WD becomes a direct ingestion source, type validation must be applied upstream. Add a WD pre-ingestion check: Type must be one of GIG, STIP. Any other value routes to a WD data quality report (analogous to the OTG remediation report).
Low impact now — critical once WD is a direct source
