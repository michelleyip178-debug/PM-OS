OTEP — Audience Ringfencing Analysis

OTG allows opportunity owners to restrict visibility by agency (Location), Business Unit, or Function. This analysis quantifies how prevalent ringfencing is and what it means for OTEP ingestion.  ·  Source: RAW_GIG_AUDIENCE_FILTERS Report  ·  2,187 records, 669 currently open  ·  Updated 15 June 2026 (I-012 ratified)

This means OTEP reads the officer's agency at login and filters the catalogue accordingly — officers only see opportunities they are eligible for.

What this means for OTEP ingestion

Three options for handling ringfenced opportunities — each requires a BO decision
A — Exclude ringfenced opps
Do not ingest any opportunity with an audience filter. OTEP only serves fully WOG-open opportunities. Simple to implement — add R13: "Has Audience Filter = Yes → BLOCKED." 253 currently open opportunities would be excluded, leaving 416 open to ingest.
Loses 38%
B — Enforce ringfence in OTEP
Ingest all opportunities but apply the Location/BU/Function filter when displaying to officers. Each officer's agency is matched against the filter — they only see opportunities they're eligible for. Requires OTEP to know each officer's agency at display time. Most complete solution but highest engineering effort.
Best UX
C — Flag but ingest
Ingest all opportunities with a "Restricted" badge visible to all officers. Officers from non-eligible agencies can see but cannot apply. Reduces confusion vs Option A but may generate frustration. FormSG link may serve as a soft gate anyway (FormSG can enforce agency eligibility separately).
Partial UX
D — Ingest; ESG carve-out
Exclude ESG-ringfenced opportunities only (169 records = 67% of all ringfenced) and ingest the rest. ESG is using OTG as a pure internal HR platform — these are not intended to be WOG discovery opportunities. All other ringfenced agencies (PA, NLB, WSG: 84 records) get Option B or C treatment.
Pragmatic
Proposed new ingestion rule — R13: Audience Filter Check
Trigger: Has Audience Filter = Yes
Action (pending D6): Route to one of the four options above.
Rule type: Classification / eligibility — runs after R4 (type classification)
Data needed: GIGS_V2_REPORT currently does not include audience filter fields. The RAW_GIG_AUDIENCE_FILTERS report must be joined to GIGS_V2_REPORT on Gig ID before this rule can fire.
Affected opportunities: 253 open · 38% of pipeline intake

Ringfencing decision — confirmed (I-012)

I-012 MVP ringfencing = agency-level only (Location filter) Ratified 12 Jun 2026

What was decided: OTEP MVP enforces agency-level (Location) ringfencing only. The ingestion pipeline reads the opportunity's audience filter and stores the eligible agency list. At display time, OTEP matches the logged-in officer's agency against the filter — officers see only opportunities they are eligible for. BU and Function ringfencing (13 records total) is deferred to post-MVP.

✓ Confirmed approach: Ingest all opportunities (including ringfenced). Enforce agency-level Location filter at display time. Each officer sees only what they're eligible for. Requires officer agency to be available in OTEP session context (WOG AD / Keycloak). SJR is safe at MVP (0% ringfenced and excluded from MVP scope).
Deferred BU + Function ringfencing (13 records) — post-MVP. These are rare (HR/OD internal moves) and low-volume. Will be addressed in a follow-on sprint once agency-level enforcement is stable.
Implementation dependency: Officer agency must be readable from the session context (WOG AD or Keycloak token). OTEP-305 (Login/Logout) and Keycloak integration are the engineering prerequisite. QA carry-in OTEP-305 is Keycloak-blocked as of 15 Jun — no target date from Pow Hwee yet.
