OTEP — Ingestion Business Rules

What passes, what fails, what gets flagged — and why  ·  For BO / PM sign-off  ·  Draft as at 10 June 2026

4 possible outcomes per gig
5 pre-flight checks (applied in order)
7 field validation rules
1 extraction rule (non-blocking)
4 rules pending BO decision to finalise

The 4 possible outcomes

BLOCKED — fails a required field check. Routed to remediation report for agency to fix.
FLAGGED — passes required checks but has an amber condition (TBC field or stale). Still ingested unless BO rules otherwise.
EXCLUDED — deliberately not ingested (test entry, wrong status, policy decision). Does not appear in remediation report.
PASSES — all required fields present, no exclusion triggers. Ingested into OTEP catalogue.

At any step, a gig can exit to BLOCKED, EXCLUDED, or FLAGGED. Rules below are applied in the order shown.

Phase 1 — Pre-flight exclusion checks

R1 Status must be Open Excluded
A gig is only eligible for ingestion if its Status = "Open" at the time of the export. Any other status — Closed, Draft, Archived, Expired — is silently dropped before any other check runs.
WhyNon-Open gigs are not live opportunities. Ingesting them would surface unavailable roles to applicants.
Current data633 Open gigs in the export. All other statuses are excluded before this analysis — this is the starting population.
R2 Test entries must be excluded Excluded
A gig is excluded if its GigName contains "Testing", or if its GigID matches a known sandbox record. Currently: GigIDs 13733, 14807, 14813 are confirmed test entries with Open status.
WhyTest entries are sandbox records, not real opportunities. They must never appear on the OTEP platform.
Exception handlingThe list of known test IDs should be maintained by the ingestion pipeline team and updated as new test entries are identified.
R3 Stale gig handling BO decision needed
A gig is stale when its end_date has passed but its Status is still Open. Currently 346 gigs are stale; 255 of those have zero applicants; 74 expired over a year ago.
BO must choose one of:
A. Exclude all stale gigs (safest for applicant trust)
B. Exclude stale + zero-applicant gigs only (255 excluded)
C. Ingest stale gigs with a "closing soon" indicator
D. Ingest all as-is (no stale logic)
Impact of each option
A → 346 fewer gigs in OTEP at launch
B → 255 fewer gigs; 91 stale-but-active remain
C → requires new field in OTEP schema
D → applicants may apply to expired roles

Phase 2 — Type classification

R4 Opportunity type is derived from the GigName prefix Classification
Every gig must have a [type prefix] at the start of its GigName — e.g. [Gig] Data Analyst role at MTI. The prefix is extracted and matched to one of 6 recognised types.

R5 Gigs with no type prefix — handling TBC BO decision needed
If GigName does not start with a [prefix], the gig cannot be typed. Currently 78 gigs have no prefix — mostly from MSF (37) and Enterprise Singapore (19). Based on naming patterns, most are likely Jobs or Secondments.
BO must choose one of:
A. Hard block — route to remediation report, require agencies to add a prefix (recommended)
B. Ingest as "Uncategorised" — display without type, no TC validation
C. Attempt keyword inference — classify from GigName body (fragile, needs ongoing maintenance)
Recommended: Option A
Requiring a prefix enforces minimal data quality without guessing. Agencies already use the convention — these are outliers. A clear report message tells them exactly what to add.

Phase 3 — Field validation rules

R6 Agency (LocationName) must be present — all types Blocked
Every gig must have a named owning agency. A blank or null agency is a hard block — OTEP cannot display the gig without knowing who posted it, and there is no owner to contact for remediation.
Current impact27 gigs across all types are missing agency. 7 are owned by a shared inbox (otg@psd.gov.sg) — technically present but effectively uncontactable.
Note on shared inboxGigs owned by otg@psd.gov.sg are not hard-blocked (agency field is populated) but are flagged in the remediation report as having no individual owner.
R7 Business Unit must be present — all types Blocked
Every gig must have a Business Unit set. This is displayed on the OTEP listing and is required for organisational filtering.
Current impactWorst in Other (TBC) type: 23 of 56 missing. Also present in Secondment (7), Job (7), Gig (4), and No tag (6).
WhyWithout BU, OTEP cannot route or filter the opportunity by organisational structure. It is a core metadata field.
R8 Function must be present — ruling to confirm BO to confirm
Function is currently treated as required for all types. However, short-term gigs and STIPs may not map cleanly to a single function. BO to confirm whether a missing Function should hard-block ingestion for all types, or only for permanent/long-term opportunities.
Current impact174 gigs missing Function across all types. Largest gaps: Other TBC (31), Secondment (52), Job (41), Gig (13). If confirmed required for all: all 174 remain blocked.
Recommended positionRequire Function for all types. It is the primary discoverability filter on OTEP — without it, applicants cannot find the opportunity when browsing by function area.
R9 Start date must be present — Secondment/Job exceptions under discussion BO to confirm
Start date is currently treated as required for all types. However, Secondments (200 missing) and some permanent Jobs may be evergreen — standing opportunities with no fixed start date. BO to rule whether these types may omit start date if the role is ongoing.
Current impact288 gigs missing start date — the single largest blocker. Secondment accounts for 200 of these. If Secondments are exempted, the blocked count drops by up to 200.
If exemption grantedA new "evergreen" indicator would need to be added to the ingestion schema, or the exemption is applied at the type level only (Secondment = start date optional). Recommend the latter — simpler to implement.
R10 End date must be present — all types Blocked
Every gig must have an end date. This is used both for display on the OTEP listing and for staleness detection (Rule R3). No exceptions proposed for any type.
Current impact51 gigs missing end date. Secondment accounts for 38. If start date is exempted for Secondments but end date is not, these remain blocked.
Why no exceptionWithout an end date, OTEP cannot determine when to delist the opportunity. An open-ended role can still be given a far-future end date by the agency.
R11 Time commitment — required for Gig and STIP only Blocked (Gig/STIP) · TBC (others)
Time commitment is a hard required field for Gig and STIP — these are short-term assignments where duration is a core applicant expectation. It is not required for Secondment, Job, or SJR. For agilePSD and Other (TBC) types, the rule awaits BO confirmation.
Current impactGig: 5 missing TC (hard blocked). STIP: all 7 have TC (no block). agilePSD: 29 gigs with TC absent — if required, all 29 become blocked; if not, only 5 remain blocked (missing Function).
Recommended position for TBC typesTreat agilePSD as job/secondment-equivalent → TC not required. Treat Other (TBC) on a per-tag basis — some variants (e.g. Innofest) are likely project-based and should require TC.

Phase 4 — Field extraction (non-blocking)

R12 FormSG URL — extract from description, never blocks ingestion Extract
After a gig passes all field validation checks, the ingestion pipeline scans the description field for a FormSG URL matching the pattern https://form.gov.sg/[alphanumeric ID]. The first match is extracted and saved as formsg_url. This field is never a hard requirement — a missing URL is handled gracefully in the UI.
If FormSG URL foundSaved as formsg_url on the OTEP opportunity record. The "Apply via FormSG" button on the listing links directly to this URL, routing applicants to the application form.
If no FormSG URL foundThe "Apply via FormSG" button is replaced with a message: "No FormSG URL available. Please contact the agency who posted this opportunity." The gig is still ingested and visible in OTEP.
What to look forFormSG URLs follow the format https://form.gov.sg/XXXXXXXXXX where the ID is alphanumeric. The description may contain it as a hyperlink, inline text, or labelled "Apply here:" — the regex extracts the URL regardless of surrounding text.
Action needed before implementationConfirm which OTG source column contains the opportunity description — this field index is not yet mapped. Check that the description column is included in the export used for ingestion.
