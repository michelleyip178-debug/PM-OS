The 4 possible outcomes

BLOCKED — fails a required field check. Routed to remediation report for agency to fix.
FLAGGED — passes required checks but has an amber condition (TBC field or stale). Still ingested unless BO rules otherwise.
EXCLUDED — deliberately not ingested (test entry, wrong status, policy decision). Does not appear in remediation report.
PASSES — all required fields present, no exclusion triggers. Ingested into OTEP catalogue.

At any step, a opportunity can exit to BLOCKED, EXCLUDED, or FLAGGED. Rules below are applied in the order shown.

Phase 1 — Pre-flight exclusion checks

R1 Status must be Open Excluded
A opportunity is only eligible for ingestion if its Status = "Open" at the time of the export. Any other status — Closed, Draft, Archived, Expired — is silently dropped before any other check runs.
WhyNon-Open opportunities are not live opportunities. Ingesting them would surface unavailable roles to applicants.
Current data633 Open opportunities in the export. All other statuses are excluded before this analysis — this is the starting population.
R2 Test entries must be excluded Excluded
A opportunity is excluded if its GigName contains "Testing", or if its GigID matches a known sandbox record. Currently: GigIDs 13733, 14807, 14813 are confirmed test entries with Open status.
WhyTest entries are sandbox records, not real opportunities. They must never appear on the OTEP platform.
Exception handlingThe list of known test IDs should be maintained by the ingestion pipeline team and updated as new test entries are identified.
R3 Lifecycle — visible if closing_date > today OR closing_date IS NULL Confirmed — I-004
An opportunity is ingested if its closing_date is in the future or is null (evergreen). Past-date opportunities are excluded. The nil sentinel 00/01/1900 is treated as null (evergreen). Confirmed (I-004). For Job, Secondment, and SJR types where end_date is not required (R10), the staleness check is skipped entirely — these remain visible until the agency manually closes them.
Current impactPast-date records with zero applicants are excluded at this step. 51 records still blocked on missing end date — these are Gig/STIP types where end date remains required.
Evergreen handlingAgencies can set closing_date to 00/01/1900 to mark a standing role as evergreen. OTG ops can update this on behalf of agencies where needed.

Phase 2 — Type classification

R4 Opportunity type is derived from GigName prefix — matched to 5 OTEP categories Classification
Every opportunity must have a [type prefix] at the start of its GigName — e.g. [Gig] Data Analyst role at MTI. The prefix is matched to one of 5 recognised OTEP categories. Opportunities with a prefix that does not map to an OTEP category are blocked at classification — see D5.

R5 Opportunities with no recognised type prefix — hard blocked Blocked
If GigName does not start with a recognised [prefix], the opportunity is hard blocked. Currently 78 opportunities have no prefix or use an unrecognised tag (e.g. "No tag," "Other (TBC)," "agilePSD (TBC)"). OTEP cannot guess the type — agencies must correct the GigName prefix before the record can pass.
Why hard blockType is required for filtering on CareerCompass. An untyped opportunity cannot be shown in filtered views and creates a poor applicant experience. Requiring agencies to fix the prefix enforces minimal data quality and takes only minutes per record.
Current impact78 records blocked — MSF (37), ESG (19), others (22). These are the top remaining blocker after v3 rule changes. The remediation report (v3) includes the full GigID list per agency.

Phase 3 — Field validation rules

R6 Agency (LocationName) must be present — all types Blocked
Every opportunity must have a named owning agency. A blank or null agency is a hard block — OTEP cannot display the opportunity without knowing who posted it, and there is no owner to contact for remediation.
Current impact27 opportunities across all types are missing agency. 7 are owned by a shared inbox (otg@psd.gov.sg) — technically present but effectively uncontactable.
Note on shared inboxOpportunities owned by otg@psd.gov.sg are not hard-blocked (agency field is populated) but are flagged in the remediation report as having no individual owner.
R7 Business Unit must be present — all types Blocked
Every opportunity must have a Business Unit set. This is displayed on the OTEP listing and is required for organisational filtering.
Current impactWorst in Other (TBC) type: 23 of 56 missing. Also present in Secondment (7), Job (7), Gig (4), and No tag (6).
WhyWithout BU, OTEP cannot route or filter the opportunity by organisational structure. It is a core metadata field.
R8 Function — optional for all types (display-only) Confirmed — I-014
Function is display-only — a missing Function does not block ingestion for any type. Officers browsing without a function filter see the opportunity; function-filtered views correctly exclude it. Amber (designer) handles the graceful null state on listing cards — no "Function: —" label. Confirmed 12 Jun 2026 (I-014).
Impact of this decision174 opportunities that were blocked solely on missing Function are now unblocked. These contributed to the ESG and NLB unlocks in the v3 re-run.
Implementation noteIngestion pipeline skips Function validation entirely. OTEP listing page: if Function is null, the function chip on the card is hidden (not shown as empty). Amber to confirm final null state design.
R9 Start date — Secondment, Job, SJR exempt (confirmed) Confirmed
Start date is required for Gig and STIP. It is not required for Job or Secondment — these are standing roles where a fixed start date may not be applicable. Card shows "Ongoing / No fixed start" when absent. Confirmed 12 Jun 2026 (I-015).
Impact of this decisionThe single largest unlock from the 12 Jun session. 230 Secondments (ESG, MTI) and 87 Jobs blocked on start date are now passing. Still required for Gigs and STIPs — 27 records remain blocked on this field for those types.
ImplementationExemption applied at type level — no schema change required. Ingestion pipeline skips start date validation when type ∈ {Job, Secondment}. Confirmed — no further sign-off needed.
R10 End date — Job and Secondment exempt (confirmed) Confirmed — I-015
End date is required for Gig and STIP. It is not required for Job or Secondment — these are permanent or standing roles with no natural deadline for delisting. Confirmed 12 Jun 2026 (I-015, same decision as start date exemption).
Impact of this decision51 opportunities missing end date; Secondment accounts for 38. With this exemption, those Secondment opportunities are no longer blocked on end date. Staleness detection (R3) does not apply to these types when end date is absent.
Staleness handlingFor Secondment/Job/SJR with no end date, R3 staleness check is skipped. These opportunities remain in OTEP until the agency manually closes or delists them.
R11 Time commitment — required for Gig and STIP only Confirmed — I-013
Time commitment is a hard required field for Gig and STIP — these are short-term assignments where duration is a core applicant expectation. It is not required for Job or Secondment — these are full-time roles by nature. Confirmed 12 Jun 2026 (I-013).
Current impactGig: 5 records still missing TC (hard blocked — agency must add hours/week and dates). STIP: all passing on TC. Job/Secondment: TC validation skipped entirely. This closed a rule misfit that had been blocking 5 Jobs incorrectly.
ImplementationTC validation fires only when type ∈ {Gig, STIP}. No schema change required. Records that were previously blocked as Jobs due to missing TC now pass this check.

Phase 4 — Field extraction (non-blocking)

R12 FormSG URL — extract from description, never blocks ingestion Extract
After a opportunity passes all field validation checks, the ingestion pipeline scans the description field for a FormSG URL matching the pattern https://form.gov.sg/[alphanumeric ID]. The first match is extracted and saved as formsg_url. This field is never a hard requirement — a missing URL is handled gracefully in the UI.
If FormSG URL foundSaved as formsg_url on the OTEP opportunity record. The "Apply via FormSG" button on the listing links directly to this URL, routing applicants to the application form.
If no FormSG URL foundThe "Apply via FormSG" button is replaced with a message: "No FormSG URL available. Please contact the agency who posted this opportunity." The opportunity is still ingested and visible in OTEP.
What to look forFormSG URLs follow the format https://form.gov.sg/XXXXXXXXXX where the ID is alphanumeric. The description may contain it as a hyperlink, inline text, or labelled "Apply here:" — the regex extracts the URL regardless of surrounding text.
Action needed before implementationConfirm which OTG source column contains the opportunity description — this field index is not yet mapped. Check that the description column is included in the export used for ingestion.
