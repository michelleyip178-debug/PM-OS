# GovTech Singapore ICT RMM Baseline Risk Register & Controls Library
*Version 1.01 (Optimized Reference Library for Public Sector Risk Scenario Assessments)*

> **Saved to PM-OS 2026-09-03.** Companion to `govtech-ict-rmm-methodology.md`. Reference for Career Compass pre-go-live risk assessment. Career Compass profile for filtering: **Intranet Application**, processes **entity information** (officer personal/employment/competency data), Ministry-owned (PSD), not CII/SII, integrates with POCDEX / CSC / Jumpstart / WOG AD. Use the Intranet App column to determine mandatory baseline risks.

This reference library contains GovTech Singapore's official baseline risk scenarios, risk statements, recommended controls, and system applicability criteria under the **ICT Risk Management Methodology (ICT RMM)**.

It is designed to serve as a structured knowledge library for **Claude** (and other Large Language Models) to automate Stage 2 (Identify Risks) and Stage 4 (Treat Risks) of the ICT RMM process, evaluate risk registers, verify security compliance, and generate grounded project risk matrices.

## 1. System Prompt & Instructions for Claude
When analyzing a system's scope, performing risk identification, or recommending mitigations, use the rules and datasets in this document.

### 1.1 Instructions for Automatic Risk Scoping & Filtering
1.  **Read System Characteristics (Stage 1 Scope):** Identify if the system under assessment has the following classifications:
    *   **CII/SII:** Critical Information Infrastructure or System of Importance (Criticality).
    *   **Internet Application:** Web-facing application accessible via the public Internet.
    *   **Intranet Application:** Internal application accessible only within Government intranet/internal networks.
    *   **Infrastructure:** Underlying hosting, network, or server environments.
2.  **Filter Baseline Risks:** For each baseline risk in the tables below:
    *   Check the system's characteristic against the applicability columns (**CII/SII**, **Internet**, **Intranet**, **Infrastructure**).
    *   If a cell contains **"Y"**, and the system matches that characteristic, this risk scenario **MUST** be included in the system's draft Risk Register.
    *   If a cell is blank, the risk is not mandatory for that specific characteristic (though still optional if contextually relevant).
3.  **Generate Risk Register (Stage 2):** Produce a standardized risk register matching the tables below, including the **Risk Category**, **Risk Scenario**, **Risk Statement**, and **Recommended Controls** (for Project Risks) or default mitigations.

### 1.2 Standardization Guidelines
*   **Risk Scenario vs. Category:** Do not change the Risk Scenario classifications in the tables below; they represent official GovTech naming baselines.
*   **Do Not Modify Risk Statements:** Preserve the exact wording of the baseline risk statements in assessments to maintain auditability against GovTech's reference standards.
