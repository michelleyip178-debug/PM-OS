## The Decision

**R1 Epic C (status tracking) is locked as World B: fully OTEP-native, no external ATS/HRPS/Cumulus integration**, per D-030 and the CIO's 2026-07-07 confirmation. This is now written into the canonical R1 PRD (Section 6, "Solution Overview").

### What World B means architecturally

OTEP owns all three records natively, with no external system in the loop:
- **Epic A** — the posting record
- **Epic B** — the application record
- **Epic C** — the full status state machine (Submitted → Under Review → Outcome)

Existing OTG/C@G postings continue to ingest read-only in parallel, unchanged from MVP.

### What this is NOT

Per the R1 PRD's Non-Goal #1: OTEP does not become a system of record for HR or a de facto ATS replacement. OTEP's status state machine governs only applications submitted through CareerCompass itself — it doesn't sync to, represent, or take over status-of-record responsibility from any external system. This boundary exists specifically because Barry raised the concern that creation + status tracking together start to resemble Compass becoming the ATS. It doesn't — Compass owns its own records, not HR's system of record.
