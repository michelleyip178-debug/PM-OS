Officer journey · Internal Jobs (AS-IS vs. TO-BE)

Finding an internal job, before and after

Internal Jobs isn't a development programme with a nomination cycle, it's a full posting change, and today it lives entirely outside CareerCompass, split across two legacy portals. This maps how discovery changes once Compass becomes the front door. Source: Internal Jobs architecture diagram (shared Sep 2026) and the Mobility Programmes comparison artifact.

Read this differently from the IJR/SJR maps: those two lanes are two live paths an officer can be on at the same time this year (structured vs. officer-initiated). Here, the two lanes are sequential states of the same system: AS-IS is what's true today, TO-BE is the target architecture. An officer doesn't choose between them, the system moves from one to the other.

R1 scope boundary: only Phase 01 (Discovery) is committed R1 scope, and it depends on an undelivered HRPS API with no date yet (R-07, 🔴 Red). Phases 02–04 are target-state architecture, not R1 deliverables. Apply-as-redirect is decided, not open, but it's still gated on that same API access landing. Ringfencing for Discovery is agency-level only, simpler than IJR's — the open question now is whether HRPS supplies that ringfencing data or Compass has to build it.

What actually gets better

Discovery. An officer no longer has to know two systems exist, remember two logins, or check both to be sure they've seen every posting. Apply routes cleanly to whichever system hosts the posting, so nobody's stuck guessing where to go.

What's still open

  • Whether HRPS supplies ringfencing/agency-tagging data directly, or Compass has to build that logic itself
  • Delivery date for the HRPS API access this whole discovery flow depends on (R-07)
  • Timeline — can't firm up until the API dependency clears

This isn't a development programme with a cycle. Unlike IJR or SJR, there's no nomination window, and the ringfencing is simpler: agency-level only, any officer within the agency can see and apply, no individual eligibility layer on top (confirmed by BOs, 23 Sep — this is the one real structural difference from IJR, which can add agency-defined per-officer criteria like minimum tenure). Internal Jobs is a full, permanent posting change, and today it's entirely a data-architecture problem, not a CareerCompass feature.

Don't read TO-BE as "Compass takes over." Compass pulls from HRPS on a periodic sync and never holds or maintains the data — that stays entirely in the HR systems. Apply redirects out to whichever system hosts the posting; it's not a native in-app application.
